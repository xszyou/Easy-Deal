## 全书地图

原书的骨架是第 1 章提出的 **ML4T 工作流**：底层是数据基础设施，上层是一个不断循环的策略研究过程。27 章大致分成 6 个部分：

| 部分 | 章节 | 回答的问题 |
|---|---|---|
| 总纲 | 第 1 章 | 为什么流程比模型更重要？ |
| 一、数据基础设施 | 第 2–5 章 | 数据从哪来、怎么存、怎么保证「当时真的知道」？ |
| 二、研究框架与特征 | 第 6–10 章 | 怎么定义问题、设计标签、造特征，同时不骗自己？ |
| 三、模型 | 第 11–15 章 | 从线性模型到树模型、深度学习、因子模型、因果机器学习，各自什么时候用？ |
| 四、策略与风控 | 第 16–21 章 | 信号怎么变成交易？回测、组合、成本、风控、强化学习 |
| 五、AI 研究工具 | 第 22–24 章 | RAG、知识图谱、AI Agent 怎么给研究提速？ |
| 六、实盘与治理 | 第 25–27 章 | 怎么上线、监控、管理策略的整个生命周期？ |

## 三条阅读路线

**路线 A：想先建立正确的研究习惯（推荐所有人）**
第 1 章 → 第 6 章 → 第 7 章 → 第 16 章 → 第 18 章 → 第 27 章

- **一句话读懂**：一句话概括本章核心。
- **先说结论**：没时间时只看这几条。
- **分节讲解**：按原书小节顺序，用自己的话重新讲一遍。
- 💡 **类比**：把抽象概念换成生活里的例子。
- 🧭 **对你的启发**：和个人量化、EA 开发相关的提醒。
- **本章小结 + 术语对照表**：方便复习，也方便回头查原书。

## 贯穿全书的五条「铁律」

在读具体章节之前，先记住这五条。全书几乎每一章都在从不同角度重复它们：

1. **时点正确**：任何时刻，只能用那个时刻真实能拿到的信息。
2. **尊重时间顺序验证**：不打乱时间，用滚动前推（walk-forward）的方式验证。
3. **给搜索记账**：试了多少次就要承认多少次，结果按试的次数打折。
4. **扣完成本再说话**：预测准不等于能赚钱。
5. **事先写好退出规则**：什么情况下重新训练、暂停、下线，提前定好，不临场拍脑袋。

## 章节目录

| 文件 | 章节 | 一句话读懂 |
|---|---|---|
| `ML4T中文导读/ch01.md` | 第 1 章　流程才是你的护城河 | 市场一直在变，没有哪个模型能一直赢。能长期活下来的，是一套「提想法 → 验证 → 上线 → 监控 → 淘汰」的纪律化流程。 |
| `ML4T中文导读/ch02.md` | 第 2 章　金融数据宇宙 | 数据不是「下载下来就能用」的原材料，每份数据都自带一套定义和陷阱。先搞清楚你手里是什么数据、它在什么时候才可知、它可能错在哪，再谈建模。 |
| `ML4T中文导读/ch03.md` | 第 3 章　市场微观结构 | 价格不是天上掉下来的一条曲线，而是撮合引擎按规则把买卖订单配对后的产物。看懂这套机制，你才知道数据代表什么、K 线该怎么切、回测里的成交假设靠不靠谱。 |
| `ML4T中文导读/ch04.md` | 第 4 章　基本面数据与另类数据 | 行情告诉你「发生了什么」，基本面和另类数据帮你解释「为什么」。但这类数据最难的不是算法，而是两件工程活：时间要对（只用当时已知的版本），身份要对（不同来源说的是同一家公司）。 |
| `ML4T中文导读/ch05.md` | 第 5 章　合成金融数据 | 历史只走过一条路，回测好看可能只是这条路恰好对你有利。合成数据的作用，是用学到的模型生成很多条「也可能发生」的历史，把策略表现从一个数字变成一个分布，用来检验稳健性，而不是用来预测。 |
| `ML4T中文导读/ch06.md` | 第 6 章　策略研究框架：把一个想法变成可信的证据 | 想法人人都有，难的是让它变成「扣完成本、经得起反复折腾、样本外也成立」的证据。这一章给你一份研究合同：先把交易设定、评价标准、验证方法和记账方式钉死，再开始大规模试验。 |
| `ML4T中文导读/ch06_精讲.md` | 第 6 章精讲　策略研究框架 | 在第 6 章导读基础上加深：逐节讲清论证思路，拆解 7 个易读歪的地方，附研究立项单模板和练习。 |
| `ML4T中文导读/ch07.md` | 第 7 章　定义学习任务：标签、诊断与「这个特征到底靠不靠谱」 | 模型的上限由你提的问题决定。这一章教你把「预测什么」定义清楚（标签），把输入处理干净（预处理），再用一套逐折评估、多重检验修正和因果常识检查，判断一个特征是该继续、该修改还是该放弃。 |
| `ML4T中文导读/ch08.md` | 第 8 章　金融特征工程：把交易逻辑翻译成模型看得懂的输入 | 特征不是随手堆指标，而是「一个经济假设的可计算版本」。先对齐周期、说清驱动机制、分清是信号还是状态，再按家族设计、组合和去重，并且把每一次尝试都记进账本。 |
| `ML4T中文导读/ch09.md` | 第 9 章　基于模型的特征提取：让拟合的模型替你「看见」隐藏结构 | 滚动窗口公式只能描述「窗口里发生了什么」，却回答不了「冲击要多久才消退」「市场眼下处于哪种状态」「价格是沿着什么路线走过来的」。本章的思路是先拟合一个模型，再把模型吐出来的东西（状态、残差、条件波动、概率、置信程度）当特征用，而且每一步只许用当时已知的数据。 |
| `ML4T中文导读/ch10.md` | 第 10 章　文本特征工程 | 新闻、财报、电话会纪要里藏着价格图上看不到的信息，但把文字变成能回测的交易特征，难点往往不在模型多先进，而在「这段文字到底什么时候能用」「有没有偷看未来」。 |
| `ML4T中文导读/ch11.md` | 第 11 章　机器学习流水线：从线性基准开始 | 先用最朴素的正则化线性模型，把「防泄露的滚动验证、SHAP 体检、共形区间」这一整套流程跑通，它就是后面所有复杂模型必须先打赢的那条及格线。 |
| `ML4T中文导读/ch12.md` | 第 12 章　表格数据的进阶模型：梯度提升树及其挑战者 | 梯度提升树（GBM）是金融表格数据的默认主力，擅长「分情况讨论」；库怎么选是工程问题，模型能不能用是验证问题。它在九个案例里把有信号的数量从三个提到五个，但也有输给线性模型的时候。 |
| `ML4T中文导读/ch13.md` | 第 13 章　时间序列深度学习 | 别急着上 Transformer。先回答三个问题：序列的先后顺序在你的数据里到底有没有额外信息？你要的是一条未来路径，还是一个终点数字？你的模型能不能先赢过一层线性映射？ |
| `ML4T中文导读/ch14.md` | 第 14 章　潜在因子模型：从「因子动物园」里找出真结构 | 与其一个个去试几百个「因子」，不如让收益数据自己交代背后有几股共同力量；但要时刻分清，「让大家一起动」和「长期给你付钱」是两回事。 |
| `ML4T中文导读/ch15.md` | 第 15 章　因果机器学习：从「相关」走到「谁导致了谁」 | 会预测不等于懂原因。这一章用双重机器学习（DML）、贝叶斯结构时间序列（BSTS）和因果发现算法，教你把一个「看着有关系」的说法放到火上烤一烤，看它是能扛住，还是一碰就碎。 |
| `ML4T中文导读/ch16.md` | 第 16 章　策略模拟：回测是用来「推翻」策略的 | 一个预测模型离赚钱还差一整套「交易规矩」。回测的价值不在于证明策略好，而在于在花真钱之前，尽可能多地找出它不行的理由。 |
| `ML4T中文导读/ch17.md` | 第 17 章　组合构建：把预测变成仓位 | 从「模型打分」到「每个品种放多少钱」，中间这一步本身就是一个会出错、会过拟合的模型。简单的分配规则出奇地难打败，精巧的优化器反而常把估计误差放大成集中押注。 |
| `ML4T中文导读/ch18.md` | 第 18 章　交易成本：纸面利润和真实利润之间的那道墙 | 回测里的漂亮收益，从第一笔真实成交开始就在缩水。成本不是回测跑完后「扣个百分比」的收尾工作，而是从挑因子到上线监控每一步都要考虑的硬约束。 |
| `ML4T中文导读/ch19.md` | 第 19 章　风险管理：把回测冠军改造成能上战场的系统 | 风控不是回测之后附带的一张报表，而是系统设计本身——事先写清楚「情况变坏时，策略可以做什么、必须做什么」。没有成文风控规则的策略，只是一个还没被压力考验过的假设。 |
| `ML4T中文导读/ch20.md` | 第 20 章　策略综合：九个案例放在一起看，到底说明了什么 | 同一套流程在九个市场上各跑一遍，得到的是一份冷静的成绩单：预测能力普遍很弱，验证期漂亮不代表留出期能活；真正决定成败的，常常是标签、成本、流动性和市场环境，而不是模型有多高级。 |
| `ML4T中文导读/ch21.md` | 第 21 章　强化学习：让模型学会「怎么做」，而不只是「会怎样」 | 监督学习回答「接下来可能发生什么」，强化学习回答「现在该做什么」。在金融里，它最靠谱的用武之地不是找 alpha，而是执行、做市和对冲这类「动作本身就是优化目标」的问题；而从模拟器到实盘的鸿沟，是它最大的障碍。 |
| `ML4T中文导读/ch22.md` | 第 22 章　用 RAG 做金融研究 | 大模型会一本正经地编数字，金融场景容不得这个。RAG 的办法是让模型「只看你给它的材料说话」，并且每句话都能指回原文出处。它不是一句提示词技巧，而是一整套从解析文档到检查引用的工程系统。 |
| `ML4T中文导读/ch23.md` | 第 23 章　知识图谱 | 当问题的答案藏在「谁和谁有什么关系」里（供应链、持股、传导路径），按相似度找文本块就不够了，需要把实体和关系显式地画成一张图。但图的维护成本很高，只有问题真的是「关系型」的时候才值得用。 |
| `ML4T中文导读/ch24.md` | 第 24 章　自主 Agent | 金融 Agent 应该当成「工作流」来设计，而不是当成一个会聊天的「人格」。推理模式只是一层，真正决定它可不可信的，是显式状态、强类型的工具合同、受限的自主权，以及能完整重放的运行记录。本章的 Agent 只读、只出概率和研究结论，不下单。 |
| `ML4T中文导读/ch25.md` | 第 25 章　实盘交易系统 | 大多数量化项目不是死在「策略没有优势」，而是死在「实盘系统和回测系统悄悄算得不一样」。办法是让同一份策略代码同时跑回测和实盘，再逐级验证数据、特征、预测、信号、订单都一致，最后靠开机检查、分级熔断和逐步加仓守住真金白银。 |
| `ML4T中文导读/ch26.md` | 第 26 章　MLOps 与治理 | 上线不是终点，每个模型都会衰退。这一章讲上线之后怎么「早发现、稳应对、自动兜底」：用数据闸门、滚动指标和漂移检测发现问题，用影子模式和分阶段放量安全换模型，用多层熔断在突发事故时自动止血。配套的 MLOps 工具要按团队规模取用，不要一上来就全套。 |
| `ML4T中文导读/ch27.md` | 第 27 章　系统化的优势 | 全书的技术会过时，单个策略会失效，真正能长期复利的是一套纪律化的流程。这一章把这个结论延伸到职业和学习上：该往哪个方向走、该读什么、该关注哪些新领域、怎样制定自己的成长计划。 |
