# 第 23 章　知识图谱

> **对应原书**：Chapter 23 *Knowledge Graphs*（第 619–639 页）
> **一句话读懂**：当问题的答案藏在「谁和谁有什么关系」里（供应链、持股、传导路径），按相似度找文本块就不够了，需要把实体和关系显式地画成一张图。但图的维护成本很高，只有问题真的是「关系型」的时候才值得用。

---

## 先说结论：这章到底想让你记住什么

如果你只有 3 分钟，记住这 5 点就够了：

1. **先问问题是不是「关系型」的。**能改写成「沿某条关系链找实体」才值得上图；查单家公司的营收、总结一堆研报，表格和向量检索更省事。
2. **建图首先是治理问题。**同一家公司只能有一个身份、关系种类要有限、每条边要带出处和时间，这比选哪个大模型做抽取更重要。
3. **Graph RAG 的分工：数据库找关系，大模型说人话。**多跳关联让图数据库确定性地执行，比让模型从零散文本里猜路径准得多、也省得多。
4. **图结构能变成特征。**中心度、供应商集中度、机构拥挤度、共同持仓相似度，都是单看一家公司看不到的风险。先用手工图特征，图神经网络在选股上的证据还很弱。
5. **事件、披露、抽取三个时间要分开记。**回测只能按披露时间放行信息，否则图特征和其他偷看未来的特征一样不可信。

下面逐个展开。

## 23.1 什么时候值得用图

上一章的 RAG 在一个个孤立的文本块里找相似内容，但有些问题的答案是一条路径。比如：「哪些公司和英伟达共用关键供应商？其中哪些供应商集中在地缘风险高的地区？」这需要先走一步找到供应商，再和其他公司的供应商取交集，再按地区筛选。图数据库里这是一次模式匹配；关系数据库要写几层自连接，过了两跳就很难维护；向量检索只能从散落的文字里「猜」出路径，这恰恰是代价最高的出错方式。

知识图谱的做法是：实体当节点，关系当有类型的边，标识符、时间、出处作为属性挂在节点和边上。

### 用一个判断清单来决定

**值得上图的信号：**

- **风险会沿网络传导。**供应链、银行间借贷、交叉持股都属于此类，单看每家公司的指标看不出来。Haldane 和 May 的研究说明，「中心辐射型」网络对随机冲击很稳，可一旦中心节点出事就会全面扩散，所谓「稳健但脆弱」。
- **一群人同时买卖同一批股票。**被同一批机构持有的股票，收益会出现基本面解释不了的联动；持仓高度集中的股票，一家机构被迫平仓，持有类似组合的其他机构可能跟着卖，形成踩踏。
- **关系本身在变化。**新增或失去一个供应商、高管跳槽、机构逐季转移仓位，这些结构变化常常先于价格变化，而在普通的表格特征里很难表达。

**不值得上图的信号：**

- **只是查某个实体的属性。**营收、市值一条记录就够了。早期项目常犯的错是把属性也做成边，平白增加查询难度。
- **瓶颈在读懂大量文本。**总结几百份研报的观点，关键不在走关系；靠社区摘要的那类 GraphRAG，价值主要在总结，向量检索加聚类往往差不多、还更便宜。
- **图太稀疏。**平均每个节点不到两三条边时，中心度和社区划分都不可靠。而且稀疏多半说明抽取没做好，不是这个领域天生如此。

> 💡 **一个简单的测试**：试着把问题改写成「找出通过某条关系链相连的实体」。改得通，就考虑图；改不通，用更简单的工具。

## 23.2 构建金融知识图谱

### 大模型改变了什么

从文本里抽「主体–关系–客体」三元组，规则系统和监督模型早就能做：规则系统在模板之内很准，出了模板就碎；监督模型要大量标注，文风一变就得重训。两者都有个通病，「先抽出来再硬塞进图」，于是出现重复实体、关系名越来越乱、出处字段缺失。大模型的真正改变是把顺序倒过来：先定好 schema，再用结构化输出约束模型直接生成图对象，团队的精力从清洗转向校验和监控。

但速度不是全部。原书的说法很干脆：一张没法重放、审计、更正的图，是负债而不是资产。

### 写提示词之前，先定三条规矩

**谁是谁。**「Apple」「Apple Inc.」「AAPL」必须落到同一个稳定 ID（比如 CIK）上，股票代码只是一个有有效期的属性（想想 Facebook 改名 Meta）。身份解析比去重难得多：代码会变、公司会拆分合并、同名可能是不同法域的不同主体。原书建议把并购、分拆、改名当作正式事件来更新身份，而不是临时打补丁。

**能连什么。**允许的关系类型列成白名单，每种关系的起点和终点类型都有约束，违规的直接拒收或送人工。

**凭什么这么说。**每条边都要能回答「出自哪份文件哪一段、哪天公开、哪个版本的抽取器在什么时候抽的」。

### 抽取流程

只挑关系密集的章节下手（10-K 一般是业务、风险因素、MD&A，跳过样板条款）→ 用 JSON Schema 或函数调用约束输出 → 合并别名，但保留原始写法作证据 → 按白名单、类型、日期合理性、出处完整性做规则校验 → 低置信度和违规的进人工复核队列。整条流程要幂等：同一份文件、同一版本抽取器，跑多少遍结果都一样。

FinReflectKG 提出的「反思式纠错」值得借鉴：模型先抽候选，再对照规则自查、提出修正，循环到收敛，特别适合把「人名 + 职位」这类混在一起的提及拆开。

### 质量不只看精度

普通 NLP 评估看不到的问题，要靠四个专门指标盯住：合乎 schema 的比例、带完整出处的边的比例、没合并掉的重复节点比例、三个时间戳逻辑自洽的比例。一次改动可能让实体识别变好、时间一致性却变差。原书给的上线参考线是 schema 合规 90% 以上、出处覆盖 95% 以上；另外保留一份冻结的「黄金样本」，每次改提示词或换模型都回归一遍。

### 案例：标普 100 供应链图

schema 刻意很小：公司、文件两类节点，供应商、客户、竞争对手三种边，证据直接存在边上。小 schema 好校验、好排错，以后再扩。

几个现实问题：10-K 里的供应链信息准确但不全，公司只披露必须说或想强调的关系，要更全得叠加商业数据，再靠身份规则对齐；大模型会把「第三方」「供应商们」这类泛称当实体抽出来，需要停用词表过滤；入库要「按标准 ID 和关系类型合并」，重跑同一份文件应该更新原有的边，而不是再插一条平行记录，否则下游路径计数会虚高。

结果：101 家公司、601 份 10-K，去重后 1,057 条有类型的关系。台积电、富士康、三星分别连着 61、33、28 家下游公司，这正是图要暴露的关系集中度。结论一句话：大模型没有取代数据纪律，只是让有纪律的建图能规模化。

## 23.3 用 Graph RAG 做确定性的关系推理

Graph RAG 的分工是：模型负责理解问题和组织语言，图数据库负责沿关系检索。它最擅长「哪些竞争对手和 X 共用供应商」「哪些机构同时持有某公司和它的关键供应商」「截至某天能看到哪些敞口」这类问题；「半导体行业面临哪些风险」这种开放叙述题仍是向量检索更合适。所以生产系统大多是混合的，先判断问题类型再分流。

### 一次查询经过哪几关

1. **分流**：图问题、文档问题还是两者都要。
2. **生成查询**：根据精简的 schema 描述写出 Cypher。很多团队不让模型自由发挥，而是准备一套参数化模板，模型只负责挑模板、填参数，攻击面小、好校验。
3. **安全检查**：在金融部署里这是硬性结构要求——只读账号、标签和关系白名单、参数化而非拼字符串、超时和行数上限、屏蔽写入与管理类关键字。
4. **执行**：返回带出处的结构化结果。
5. **作答**：把结果行原样交给模型，要求逐条引用。因为边上带着证据指针，还能顺手取回披露原文，形成「图里的行 + 原文段落」两层引用，避免「图谱说是这样」却拿不出原始证据。

历史问题一定要加**截止日期过滤**，只让当时已公开的关系参与。这不是细节，而是金融里防止偷看未来的核心机制。

还要分清两类「图检索」：一类基于显式的领域图谱做确定性遍历，适合需要溯源、可重放的受监管流程；另一类从语料中归纳主题社区再做大范围总结，适合主题综合。本章讲的是前一类。

### 效果和常见坑

评估看三件事：生成的查询是否合法、返回的论断有多少能连到证据、在历史截止条件下是否仍然正确。外部证据方面，FinDER 发现生成质量强烈受制于检索质量；FinReflectKG-MultiHop 显示在两三跳的金融推理题上，图引导检索比按页窗口检索正确率高约 24%，token 少用约 85%。配套实验在真实 13F 持仓图上，图检索证据召回 1.00，向量检索平均 0.13、持仓类问题直接为 0，而图检索的 token 只有后者的三分之一左右。

常见故障包括编造不存在的标签或属性、遍历太宽返回一堆噪声、历史查询漏了截止过滤、回答超出返回证据的范围。这些都是工程问题，靠严格的校验、保守的模板和回归测试基本能控住。图和向量结果冲突时，一般以时间更新、时间戳可靠的那条为准。

## 23.4 从图到机器学习特征

Graph RAG 回答「现在结构是什么样」，这一节把同样的结构压成表格特征，喂给梯度提升树（第 12 章）或因子模型（第 14 章）。

### 结构位置类特征

与其逐个背定义，不如想想一家公司在网络里可能扮演的角色，以及对应的指标：

| 角色 | 对应指标 | 举例 | 风险含义 |
|---|---|---|---|
| 被很多重要公司依赖的「基石」 | PageRank | 先进制程代工厂 | 它出问题，下游全受影响 |
| 卡在路径中间的「咽喉」 | 介数中心度 | 某种关键材料的唯一中间商 | 瓶颈一断，传导面很广 |
| 邻居彼此也相连的「抱团者」 | 聚类系数 | 同一产业集群里的配套厂 | 冗余高，有替代路径 |
| 交往很多的「社交型」 | 度 | 客户遍布各行业的物流商 | 直接敞口多，传导渠道多 |

这几个指标含义不同，最好各自作为特征，让下游模型自己判断哪种角色对当前任务要紧。

### 供应链与持仓类特征

**供应链**：供应商数量、与他人共享的供应商数量、单一来源数量、供应商重叠率、依赖度。一家公司如果依赖少数几个、又被别人共用的上游，即使没有任何文件明说，它在结构上也是脆弱的。图让这种集中度可以被量出来。

**机构持仓**（来自 13F）：持有机构数相对横截面中位数的拥挤度；业绩好的机构持有市值的占比（「聪明钱」集中度）；持仓在机构间的赫芬达尔集中度（同样的机构持股比例，3 家大基金拿着比 30 家小基金拿着更脆弱）；两只股票持有机构集合的 Jaccard 重合度，它能预测基本面解释不了的收益相关。

13F 的时间陷阱要记牢：季度结束后 45 天才披露，必须按披露日入库；大机构可以申请对正在建的仓位保密，之后才在修订文件里补；组合相似度这类衍生关系每季度都要重算。

### 叠加与动态

图特征最独特的价值在于跨层组合。一家公司既依赖共享供应商、又被机构扎堆持有，一旦经营出问题，会同时遭遇供应冲击和集体抛售，风险是叠加的。「供应商重叠度 × 拥挤度」「依赖度 × 持仓集中度」「介数中心度 × 持有机构数」这类交互特征就是为此设计。

结构还决定了消息传得多快：原材料冲击先到零部件厂、再到组装厂。有了带时间的事件数据，可以按传导延迟给上游事件加权，做领先–滞后特征。随时间变化的特征包括关系更替速度、PageRank 的变化、供应商数量的净增减。一家公司供应商在减少、竞争关系在增加，可能意味着它正在转型，这在季报里要很久以后才看得出来。

配套代码最后产出一张 31 列的特征表，覆盖拓扑、供应、持仓、时序、跨图五类，可以直接和前面章节的价格特征拼接。

> 🧭 **对你的启发**：外汇和黄金没有 13F 这样的持仓网络，但「拥挤度」的思路可以迁移，比如 CFTC 持仓报告里投机净头寸的极端程度，同样是「大家站在一边时容易踩踏」的信号，也同样有发布延迟要处理。

## 23.5 金融网络中的相关性与组合

### 另一种网络：从收益里估出来的

知识图谱的边是披露文件里明写的；另一条已有二十多年的研究路线，是从收益相关性里**估**出网络。Mantegna（1999）把相关系数转成距离，构建最小生成树（MST），得到一张市场组织图：相关股票扎堆，有的是连接板块的枢纽，有的在边缘独自运动。后来的研究发现，MST 能稳定还原行业结构、捕捉市场状态变化，但社区划分对估计窗口和过滤方法（MST、PMFG、随机矩阵理论）很敏感，相邻时段可能面目全非。所以两种网络的差别可以这样记：披露图的边是观察到的，噪声小，质量取决于 schema 和抽取；相关性网络的边是估计的，噪声大，质量取决于过滤方法，而过滤方法要按分析目标来选，不是无关紧要的预处理。

### 网络能帮组合做什么

处在网络中心的股票和全市场联系更紧，加进组合带来的分散效果小；边缘股票更独立。网络感知配置会给边缘股票更高权重。能否扣完成本后真的更好，要看再平衡频率、估计窗口和网络稳定性：MST 在相邻窗口间变化大，换手会吃掉理论上的分散收益。

配套实验（100 只股票，2015–2018）：等权、波动率倒数、网络分散三种组合的夏普约为 1.58、1.51、1.54，汇总指标上分不出高下。差别出现在传染模拟里：从最中心的伯克希尔施加冲击，组合受到的影响约是从边缘的美国航空施加同等冲击的 **3.8 倍**。冲击从哪里开始，比冲击有多大更重要。

### 图神经网络成熟了吗

图神经网络（GNN，如 GCN、GAT、GraphSAGE）让每个节点反复汇总邻居信息来更新自己的表示。它在金融里的成熟度高低不一，判断依据其实就是「信号够不够清楚」：欺诈检测里，异常交易网络形态鲜明、标签明确，已经可以上生产；系统性风险还处在学术研究和监管试点阶段；选股上市场接近有效、状态不平稳，扣除成本后能复现的证据很少，仍属实验性质。

配套实验也印证了这一点：在 200 只股票的相关性网络上，把 GAT 学到的 4 维嵌入加进 8 个表格因子做岭回归，信息系数反而比只用表格因子低了约 7.7%。样本和规模有限，但方向和文献的担忧一致。

务实的顺序是：先做图分析和手工特征；再试 MST、社区发现这类结构明确的组合方法；只有扣除成本、排除时间泄露后样本外确实变好，才加 GNN 或图嵌入，而且始终当补充。想要学习型表示又不想上整套 GNN，可以先试 node2vec 这类随机游走嵌入，训练快，能和手工指标并用。

## 23.6 时间完整性与防泄露评估

静态图回答「有哪些关系」，时间图回答「这些关系**什么时候能被看到**」，后者决定信号能不能交易。

### 三个时间戳

用一个自己的例子：某公司 CFO 周一辞职（事件时间），公司周四提交 8-K（披露时间），你的系统三年后批量回补历史时才把这份文件抽进图里（抽取时间）。回测里，周二、周三的模型都不该知道这件事；把抽取时间当成可见时间同样是错的。原则只有一条：**一律以披露时间作为可见性闸门**。收购可能三月谈妥四月才公告，供应关系可能存在多年才出现在 10-K 里，这些都要按公开那天算。

两类常用文件的时间特点：

- **8-K**：重大事件一般要求 4 个工作日内披露，不同事项滞后不同，Regulation FD 类信息当天公开。把同期多家公司的高管变动汇总起来，可能看出单份文件看不到的行业级动荡。
- **13F**：季末后 45 天披露，12 月 31 日的持仓按 2 月中旬的公布日入图；保密建仓期间算出的拥挤度会偏低；整份文件延迟的机构，要么在缺口期剔除，要么以修订文件日期为准。

### 快照与时序特征

做法是按披露时间筛出截止日前可见的边，构建窗口子图，对比上一窗口的新增和消失，再算更替率、中心度漂移、集中度等窗口级指标。季度窗口与基本面披露节奏对齐，更短的窗口能抓事件驱动的变化但噪声和算力都更大；窗口规则一旦选定，整个评估期不再改。由此可以造出关系更替率、中心度动量、集中度漂移、主题加速（某类关系突然变多，提示新趋势）等特征，但它们只是候选，要变成可交易的 alpha 仍得过滚动前推验证和成本检验。

### 防泄露检查表

按「要防的漏洞 → 对应做法」来记：

- 用到了当时为真但尚未公开的信息 → 按披露时间切分训练和测试，而不是事件时间。
- 借事件与披露之间的时间差泄露 → 在切分边界附近留出隔离期。
- 某条查询路径漏了过滤 → 截止过滤对所有入口强制生效，没有例外。
- 历史特征没法复现 → 记录快照哈希和抽取器版本。
- 以为图带来了提升，其实没有 → 和不用图、用静态图的简单基线对比。

配套实验载入约 2,400 条带时间的事件，以 2025-11-01 为披露截止日过滤掉约 200 条，并确认没有截止后的披露混进来。平均披露滞后约一周，平均抽取滞后约三年，后者正说明抽取时间绝不能当可见时间。

> 🧭 **对你的启发**：外汇和黄金里最接近的是经济数据：非农的统计期、公布时刻、你的数据源入库时刻也是三个时间。回测如果用了事后修正过的数值，或按统计期对齐，就是同一类泄露。

## 23.7 搭一条能上生产的图谱管道

### 选引擎：先看规模和运维偏好

原书默认用 Neo4j + Cypher，因为工具成熟、从原型到中等规模生产都顺手。换个角度看选择：如果团队不想管运维，托管云图数据库（如 Neptune）省心，但更依赖云厂商；如果图大到要做海量分析，分布式引擎（如 TigerGraph）吞吐高，复杂度也高；如果已经有 PostgreSQL、关系种类少、查询很少超过三四跳，递归 CTE 也能撑住，只是复杂路径写起来很难看。真正的硬标准是能否做严格的访问边界、查询保护和稳定的 schema 元数据，满足这些，引擎本身没那么关键。查询语言上，Cypher 简洁，Gremlin 在 AWS / Azure 生态里常见，SPARQL 是 RDF 语义网标准，背后的思路是相通的。

### 本体：别一上来就求全

金融行业本体 FIBO 有 1,200 多个类，想一步到位的团队常常卡在早期，因为本体太宽，反而看不清分析目标。更现实的做法是：核心实体对齐 CIK、CUSIP、LEI 这类通用标识；关系词汇保持精简，多数实践只用 8–15 种；类型约束和校验规则写在代码里；需要和外部系统对接时再逐步映射到 FIBO。

### 安全与演进

自然语言转查询的入口必须做到：只读账号（写权限绝不能从这里摸到）、标签 / 关系 / 属性白名单、参数化查询、超时与行数和深度上限、所有生成和执行的查询都留痕可重放。这是架构要求，不是可选加固。

schema 默认「只加不改」：新增标签、关系、属性是安全的；改名或删除要写迁移脚本并检查下游查询；边上记录抽取器版本和 schema 版本，过渡期新旧共存，需要复现时按版本过滤。

最小生产架构可以概括为：入库 → 受 schema 约束的抽取 → 规范化服务 → 读写分离的图库 → 带安全检查的检索层 → 评估工具（查询合法性、出处覆盖、时间正确性）。

## 23.8 本章小结

- 只有问题真的是关系型的，知识图谱才值回它的复杂度，这是本章的核心纪律。
- 建图既是抽取问题，更是治理问题：身份统一、schema 约束、出处追踪、时间元数据，决定了杂乱的披露文件能否变成可信的图。
- 图有两种用法：Graph RAG 把关系逻辑交给数据库、语言交给模型，支撑多跳推理；图分析把网络结构变成集中度、拥挤度、传染路径等特征。
- 手工图特征优先，GNN 在选股上证据仍弱，只作补充。
- 三时间戳贯穿始终：没有披露时间的纪律，图特征和任何带前视偏差的特征一样靠不住。

下一章《自主 Agent》会把结构化检索、记忆和证据追踪这些部件组装成能自主做研究和预测的工作流。
